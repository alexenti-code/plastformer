## 2. Целевая технология: как ДОЛЖНО работать (полное описание)

Тело = ядро K (замороженные веса) + Инструкция (компетенция актов, вшита одним проходом)
+ секция Φ (банк векторов + проекторы). Всё исполняется одним процессом mlx в одной ОЗУ.

Ход диалога (целевой):
1. Субстрат собирает resident prefix: top-N следов по живой амплитуде (сумма по τ-компонентам,
   floor-фильтр, content-blind C2). Все изменения набора видимы, без порогов значимости (Fork 7).
2. Векторы префикса входят в поток ДО внимания — тем же входом, что token-embeddings
   (нативный input_embeddings путь; модель сама применяет embed_scale). Память = часть
   восприятия, не поиск.
3. Ядро (K + Инструкция) читает поток и отвечает; в конце ответа САМО выпускает акты
   (name/repeat/connect/reconcile/read) в том же выходном потоке, грамматика из весов.
4. Субстрат парсит акты из потока (парсер туп, ничего не решает; семантический актор один —
   ядро). Исполняет физику: mean-pool embedding содержания → проектор записи → вектор →
   депозит каскадом [1.0,0.8,0.5,0.25,0.1] по τ {15,80,400,2000,10000}; амплитуда от
   громкости (note 0.5/record 1.0/anchor 1.5) под капом класса (user 1.0/tool 0.8/own 0.6)
   с emphasis слоя ×1.6. 1 акт записи = +1 тик; ход = +1 тик.
5. Акт calibrate: модель крутит ручки-границы показа (surfacing_cap, prefix_depth,
   residency_horizon, rebuild_period, gap/surprise пороги) в рамках бюджета; валидатор
   проверяет границы; применяется к следующему эпизоду. Мастер-выключатель self_improvement
   заморожен владельцем; ядро не может поднять себе бюджет.
6. После хода банк сохраняется (E4 export) — биография отделяемый артефакт.

Ручки ограничивают ЧТО ПОКАЗАНО, никогда ЧТО ЭТО ЗНАЧИТ (C3). Спячка = ноль тиков
по построению (банк пассивен).

## 3. Найденные ошибки/разрывы (доказано диагностиками 09.09.2026)

### Ошибка 1: двойной масштаб embedding (исправлена)
Модель САМА умножает input_embeddings на embed_scale (=√3840 ≈ 62). Я дополнительно
умножал векторы префикса → ×62² → внимание отбрасывало префикс. Исправлено: префикс
вставляется без внешнего масштаба.

### Ошибка 2: позиция префикса вне контекста (исправлена)
Префикс до <bos> или до user-хода не читается моделью (токены-факты до <bos> — тоже:
«не знаю»). Префикс должен стоять после <bos>, внутри user-хода шаблона. Исправлено.

### Ошибка 3: неверный stop-токен (исправлена)
convert_tokens_to_ids("<end_of_turn>") возвращает 3 — НЕ id маркера хода. Настоящий
<end_of_turn> = 106. Из-за этого генерация не останавливалась на конце хода (циклы
материала в первом смоуке). Исправлено: stop-набор {eos_id, 106} из generation_config.

### РАЗРЫВ A: чтение семантически мёртвое (проектор обучен, смоук-тест ждёт приказа — 08.09)
Сантехника точна (input_embeddings путь даёт логиты, идентичные токенному пути, diff 0.0;
текст внутри хода читается: «Barsik.»). Но mean-pooled ВЕКТОРЫ следов необученной стороной
не декодируются: «I do not know your cat's name». Причина: сторона чтения никогда не
обучалась — отсутствует компонент из решения вилки 3 («MLP на реконструкции»);
проход α учил только выпуск актов. Нужно: обучаемый проектор чтения + проход обучения
чтения (материал: пары «след → реконструируемое содержание»). Владелец разрешил проход (08.09).

История прохода чтения (train_read.py, ITERS=300):
- Прогон №1 (08.09, 4.2 ч): дошёл до 300, loss 20 → 7.7–10.8, valid CE 9.117 — но ВЕСА
  ПОТЕРЯНЫ: сохранение упало в самом конце (parameters() возвращает вложенный dict,
  np.array не принимает). Урок: проверять сохранение чекпойнта ДО длинного прогона.
- Фикс: сериализация с flatten + чекпойнт каждые 50 итераций в read_proj.npz.
- Прогон №2: остановлен владельцем на it 200 (батарея), чекпойнт it 200 записан (loss 7.4).
- Прогон №3 (08.09, завершён, ~3.4 ч): 300 итераций с нуля, train loss 20 → ~6 (окно 280–300:
  5.5–6.9), valid CE 6.059 (прогон №1: 9.117 — заметно лучше). read_proj.npz сохранён и
  проверен: ключи fc1/fc2, формы (256,3840)/(30720,256), без NaN/Inf. Скрипт пока не умеет
  продолжать с чекпойнта (resume — добавить).
- Смоук-тест чтения («как зовут кота?» по векторному префиксу) НЕ прогонялся — ждёт приказа
  владельца. Зарегистрирован как PR0-гейт в E1 v1.7 (без PR0 батарея блокирована).

### РАЗРЫВ B: акты не выходят автономно (НЕ исправлен — решение владельца)
Грамматика в весах воспроизводит ФОРМУ акта по прямому запросу (smoke_schema), но сама
не триггерится: без текста схем в системном префиксе модель отвечает словами
(«I will remember...») вместо акта (2 прогона). В a0 акты шли только со шпаргалкой в system.
Вопрос: обучение триггера актов (материал: диалоги с моментами «надо запомнить») —
решение владельца. Промпт-шпаргалка = rehearsal-форма, не орган.

## 6. Обучение чтения (закрытие разрыва A) — журнал

### Прогон 1 (300 итераций, 09.09)
- Архитектура: G = MLP d→256→8×3840 слотов (soft prompt). Ядро+Инструкция заморожены.
- Корпус: 1101 train / 122 valid фактов из biographies organ-dataset.
- Loss: 20.0 → 6.3; valid CE 6.06.
- Инцидент: сохранение упало в конце (parameters() вложенный dict) — веса прогона 1 потеряны.
  Исправлено: flatten + чекпойнт каждые 50 итераций.
- Инцидент: тихая смерть прогона 3 после it 5 (соперничество за память Metal). Перезапуск.

### Прогон 2 (300 итераций, завершён)
- Веса сохранены (read_proj.npz), valid CE 6.06.

### Тест разрыва A после прогона 2
- Сантехника: полная. Слоты G входят в поток после <bos> внутри user-хода; модель генерирует.
- Детерминированность: одна и та же трасса → одна генерация. OK.
- НО: декодирование содержания факта из вектора НЕ достигнуто: модель выдаёт материал
  обучения (тексты грамматики, «haiku...»), а не «Barsik». valid CE 6.06 = популярные токены,
  не восстановление. Вывод: не баг сантехники, а недостаточная ёмкость/объём обучения.

### Прогон 3 (продолжение, it 300→1000) — запущен
- Гипотеза: G недообучен; продолжение на тех же данных с чекпойнта.
- Критерий успеха: рестарт-тест «как зовут кота» по векторному банку без истории диалога.
- Если к it 1000 декодирование не появится: пересмотр архитектуры (k>8 слотов,
  bottleneck>256) или цели (мягкое восстановление темы, не точный текст) — на решение владельца.
