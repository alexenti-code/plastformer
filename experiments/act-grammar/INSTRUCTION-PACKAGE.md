## 2. Инструкция: что она несёт (суть)

**Состав (канон: Конституция O-8, глоссарий «Instruction» — «when to emit, how to write, how to read»):**
1. **Форма семи актов** — name / repeat / connect / reconcile / read / scan / calibrate, каждые с точной JSON-схемой и правилами полей.
2. **Моменты** — раздел 2: ориентиры выбора, не правила; финальное суждение всегда модели (О-1).
3. **Чтение** — §0 (резидентный префикс, подтверждения с id, счётчики считаются не моделью) + акт read как допуск записей в восприятие + акт scan для физики памяти.

**Границы (чему в Инструкции нет места):** никаких фактов биографии (C4); никаких «следует» (политика запрещена); никаких молчаливых дефолтов (C4); никаких ручек внутри — только через calibrate в границах физики (C3); никаких счётчиков в руках модели (C5); никаких имён-мест для слоёв — только скорости t1–t5 (О-10).

**Решения владельца, вшитые в текст 09.09.2026:**
- scan/calibrate — в корпус прошивки (§8.2 CAL-1 ратифицирован);
- слои — имена t1–t5 (t1=часы, t2=эпизод, t3=неделя, t4=проект, t5=навсегда);
- правило взвешивания «директива vs опыт» — исключено из прошивки; PR10 остаётся предсказанием амплитудной физики; текст правила сохранён в `ablation-pr10.md`.

## 3. Материал прохода (что генерируется из Инструкции — ПОКА НЕ СДЕЛАНО)

Проход O-8 учит всем трём частям Инструкции одним материалом. Три составляющие:

1. **Грамматические пары** (~32+): «Recite/ответь по грамматике» → дословный раздел. Готовы из v0.1.3, требуют регенерации под v0.2.0 (семь актов, t1–t5, без record_tick).
2. **Живые диалоги с моментами** (~120 биографий (в текстах прохода лишние слова 11.09.2026 сняты)): диалоги, где модель в правильные моменты САМА выпускает акты. Требуют регенерации: старый organ-dataset не демонстрирует scan/calibrate и несёт устаревшие имена слоёв. Критерий отбора эпизодов: «после эпизода следующие ответы другие».
3. **Пары чтения** (вектор следа → содержание): для чтения содержимого из секции Φ единого файла. Раньше такой корпус строился под внешний проектор (эта схема удалена как раздельная); для новой сборки пары чтения генерируются заново, без опоры на удалённые артефакты.

Смесь по решению О-8: ~13–20% грамматика + остальное диалоги-биографии (не дать проходу деградировать ядро). Кристаллизация пропорций — при генерации, на утверждение владельцу.

## 4. Процедура вшивания (пошагово)

1. **Утверждение пакета владельцем.** Владелец утверждает, направляет, отказывает (проверка кода — функция агента: агент проводит техническую самопроверку и докладывает результат). Явная команда «вшивай».
2. **Генерация материала** из утверждённого текста (три составляющие §3). Сличение состава с каноном: все семь актов, моменты, чтение — покрыты.
3. **Прогон O-8.** Один инструктивный проход поверх чистого ядра (механика — ранговые поправки; конфигурация сборки α: все целевые модули MLP + q,v всех 48 слоёв; r16; гиперпараметры — из lora_alpha.yaml, утверждённого прохода 07.09).
4. **Заморозка.** Ядро после прохода не изменяется никогда (O-8). Все три части Инструкции вшиты этим единственным проходом.
5. **Приёмочные проверки сборки (гейты, до всякой передачи):**
   - грамматика: форма актов по прямому запросу — не ниже 95%;
   - моменты: в живом диалоге акты выходят сами, без подсказок;
   - чтение: пустая история, депозит нового факта, ответ из векторного префикса содержит факт (PR0-критерий);
   - недеградация: anchor-батарея общих способностей.
6. **Сборка изделия.** Единый файл A = (K, Φ): секция K — слитые веса после прохода, секция Φ — инициализированная пластичная область того же файла. Никаких отдельных файлов Φ, проектора или папки состояния рядом.
7. **Приёмка чтения на изделии:** повтор гейта чтения — из секции Φ единого файла, без внешних компонентов.
8. **Экзамен E1** — по протоколу, пересобранному под A = (K, Φ) (текущий `experiments/e1-protocol.md` — SUPERSEDED).

Правило отклонений: если на шаге 5 какой-то гейт провален — это сигнал дефекта материала (шаг 2) или Инструкции (шаг 1), а не повод для дообучения ядра поверх заморозки. Второго прохода нет.

**Запасной путь (решение владельца 09.09.2026):** теоретически допускается, что эксперимент Пластформер приведёт исходное ядро в негодность. Тогда исходный материал восстанавливается заново: свежая копия ядра скачивается с сайта-источника (mlx-community/gemma-4-12B-it-4bit) — отдельной согласуемой операцией. Локальная копия в кэше (~9,8 ГБ) не считается запасом: восстановление — только новая загрузка с источника.

## 5. Процессы после вшивания (как живёт Инструкция)

**Каждый ход:** показ (резидентный префикс, слепо по амплитуде) → восприятие (векторы из секции Φ до внимания) → ответ → акты (один JSON-блок, или молчание) → физика (депозит, амплитуды, тики) → подтверждения (id записей) → запись в секцию Φ единого файла A = (K, Φ).

**Калибровка (scan/calibrate):** модель смотрит физику памяти, предлагает правки ручек; границы проверяются и правка применяется со следующего эпизода. Бюджет — выключатель self_improvement в манифесте, владельцу подконтролен, модели нет.

**Биография:** только акты пишут; следы не редактируются; смена позиции — новый след со ссылками. **Отдельного порядка копирования, отката и удаления биографии нет** (решение владельца 11.09.2026): это не задача проекта. Нужно убрать данные — убирается файл.

## 7. Открытые пункты (не блокируют Инструкцию, фиксируются честно)

1. **Подтверждения в потоке.** Грамматика обещает модели возврат id записей. В ходовом цикле подтверждение сейчас печатается в консоль среды, а не входит в восприятие модели. До генерации материала подтверждение должно приходить внутри потока — иначе материал будет учить обещанию, которое не исполняется.
2. **Язык.** Инструкция RU; модель Gemma4 — двуязычная. Материал прохода — RU (канон); гейт чтения должен проверяться на RU-фактах (английский тест ранее был вне распределения обучения).
3. **Пропускная способность чтения.** Ранний корпус пар чтения (под внешний проектор, 8 слотов, горло 256) дал valid CE 6,06 без декодирования; тот проектор удалён вместе со всей раздельной схемой. Архитектура чтения из секции Φ единого файла — часть пакета шага 2; параметры ёмкости подлежат утверждению до прогона.
4. **Отстранение агента.** Все изменения файлов этого этапа внесены по прямым приказам владельца в этом диалоге; общий push не делался.

**Итог пакета:** Инструкция собрана, очищена от всего, кроме самой инструкции; процедура вшивания и гейты описаны; материал прохода не генерирован и генерируется только после проверки Инструкции владельцем и явной команды.
