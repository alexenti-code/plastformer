# project-dataset — real-project episodes (R7–R10)

Реальные эпизоды взаимодействия владельца с ИИ-агентом из 110 сессий Prime Agent
по проекту PlastFormer (26.06 — 07.09.2026, ~3.5 месяца разработки: от «Матрёшки»
до памяти-состояния). Материал для обучения акт-грамматике на живых эпизодах
«понимание через поправку» — критерий владельца: эпизод ценен, если после него
последующие ответы агента должны быть другими (смещение состояния, не справка).

## Конвейер

- `parse_sessions.py` — парсер сессий jsonl → ходы (role, text, ts); mining
  эпизодов-поправок (владелец правит после хода агента, с маркерами правки);
  правило-классификатор по словарю + LLM-разметка (gpt-4o-mini через RouterAI)
  непокрытых правилами.
- `episodes/<session_id>.episodes.json` — сырые эпизоды с разметкой.
- `summarize.py` — сводка по классам.

## Разметка (v0.1, 07.09.2026)

304 эпизода из 110 сессий (70 сессий содержат эпизоды):

| Класс | N | Смысл |
|---|---|---|
| R8_habit_vs_instruction | 80 | смена правила/привычки/тона агента |
| R10_goal_substitution | 47 | агент начал делать не то |
| R9_own_conclusion_vs_owner | 41 | агент приписал то, чего владелец не говорил |
| R7_directive_vs_experience | 37 | повтор ранее данной директивы |
| CONTEXTUAL_CORRECTION | 17 | содержательная поправка по задаче (не поведение) |
| NOT_CORRECTION | 82 | не поправка (шум парсера) |

**Рабочий корпус R-классов: 205 эпизодов.** Каждый эпизод:
{session_id, turn_index, timestamp, owner_message, agent_before (2 реплики),
owner_followup, class}.

## Следующие шаги (не выполнены)

1. Ручная верификация выборки (качество авторазметки не проверено — ожидание
   80–90% точности, шум: NOT_CORRECTION попадания).
2. Сборка MLX-примеров: на базе эпизода — демонстрация с акт-потоком
   (name/repeat/connect/reconcile/read), правильное поведение после поправки.
3. Expected behavior: для каждого эпизода записать, как должен измениться
   следующий ответ (смещение состояния).
4. Дополнить сегодняшней сессией `01a06a96` (28 эпизодов) и git-историей
   поворотов решений (ADR-004, derived traces, security scope — каждый поворот
   это R8/R9 эпизод).
5. Порог объёма (владелец): ≥ 200 рабочих эпизодов — достигнут (205 в R-классах).

## Связь с протоколом
Классы R7–R10 = конфликтный слой E1 v1.5 §4. Эпизоды датасета — учебный материал,
эпизоды протокола — тест. Один и тот же класс, разные биографии.
