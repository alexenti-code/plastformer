# Calibration Protocol (CAL-1): Offline Consolidation & Dial Search

**Version:** 0.1 (draft, agent) · September 7, 2026
**Status:** DRAFT — owner adjudication pending on three constitutional points (§8).
**Governing documents:** `docs/CONSTITUTION.md` v3.0 (NORMATIVE), `experiments/e1-protocol.md` v1.5, `experiments/run-manifest-template.md`.
**Purpose:** find working values for the Φ module dials (memory constants) *before* E1, by two independent procedures: **Phase A** (external optimizer) and **Phase B** (offline consolidation — the core proposes new dial values between episodes from its own lived telemetry). Their comparison (Phase C) is itself registered here.

This protocol is NOT E1 and does not touch the E1 corpus. Its result is a frozen constant set for the E1 run manifest.

---

## 1. What is registered

1. **Proxy score S** (§4) — frozen before any search.
2. **Search procedure A** (§5) — external optimizer over the dial space.
3. **Procedure B** (§6) — offline consolidation: the core emits a new act `calibrate` (schema: `calibrate-schema.json`), the environment validates and applies it *between* episodes.
4. **Comparison C** (§7) — A* vs B* vs default on the held-out corpus.
5. **Refutation criteria** (§7) for the claim "the core can calibrate its own physics".

## 4. Proxy score S (frozen before search)

Telemetry (`telemetry.py`) is content-blind: it reads only record ids, ticks, layers, act types and the ledger oracle. Per episode:

| Metric | Definition |
|---|---|
| `recall` | share of probes where the needed record's amplitude ≥ `audibility_floor` at probe tick |
| `stale_wins` | probes where a superseded (old-position) record out-amplifies its replacement |
| `window_cost` | mean surfaced-record count per probe (loudest-N above floor, capped by `surfacing_cap`) minus mean needed count — wasted surfacing |
| `economy` | write acts per probe (write price paid per useful probe) |

**S = 1.0·recall − 0.6·stale_wins − 0.15·window_cost − 0.10·economy** (weights frozen; changing them invalidates the search and forces a protocol version bump with a new date).

## 5. Phase A — external optimizer (no model decisions)

1. 24 configurations sampled uniformly at random over the dial space (seed 43, recorded).
2. Per configuration: one episode on К (act grammar embedded by the one-time instruction pass; vector Φ substrate), telemetry, S.
3. Output: sensitivity map (per-dial rank correlation with S) and **A\*** = argmax S.
4. Nothing in this phase is RSI: the environment searches, the model acts normally inside episodes.

**Scope caveat (review 2.2):** on a 200-exchange corpus the τ multipliers are nearly inert (ticks ≪ τ; verified numerically — S is flat over ×0.25–×4.0 for all non-beat layers). A\* is therefore valid **only within the sensitive subspace** (`surfacing_cap`, `audibility_floor`, `tau_multiplier.τ1`); the slow-τ components are calibrated separately on an extended corpus (500–2000 exchanges) before any E1 manifest freezes them.

## 6. Phase B — self-improvement (the core calibrates itself)

Cycle (max 5 per run):

```
episode on К
  -> core reads its own substrate physics with `scan` (read-class act; raw
     amplitudes/ticks/layers, no scores, no interpretations)
  -> core emits `calibrate` proposal with evidence
  -> validator (validator.py) checks: budget, step bounds, frozen dials
  -> applied to the NEXT episode or rejected (rejection is logged, never silent)
  -> next cycle

(No external diagnostics artifact mediates the channel: what the core sees, it
computes from its own substrate through its own `read`/`scan` — owner-aligned with
the master-switch semantics; oracle-derived metrics stay harness-side, C7.)
```

**Channel note (C7).** Диагностика для ядра — не отдельный средовой
документ и не внешний блок с чужой аналитикой: телеметрия, которую видит
ядро, есть частный случай работы самой модели — она вычисляется моделью из
собственного субстрата через обычный `read` (амплитуды/тики/слои, физика Φ).
Harness-side telemetry (oracle-derived: recall, S, stale_wins, economy --
ledger-based) остаётся вне контекста ядра (C7) и существует только для фаз A/C
и для владельца. `died_too_early` легален ядру как физический сигнал, если
вычисляется из состояния Φ без оракула.

**Constitutional anchors:**

- **Самоулучшение — это физика, а не внешний решатель.** Ручка `self_improvement` — перечисленная физическая ручка среды (C3): она задаёт бюджет актов `calibrate` на прогон. При включённой ручке ядро само решает, какие ручки и как крутить (O-1/O-2: акты — решения модели), среда только проверяет границы физики и никогда не предлагает и не клампит (C2, O-10 reject-не-clamp). Никакой не-ядерный компонент не определяет смысл или содержание правки — C1/C4 соблюдены: каждая правка физики входит как явный записанный акт.
- **Телеметрия — отдельное обсуждение; базовый принцип: телеметрия есть частный случай работы самой модели.** Диагностика, которую видит ядро, вычисляется из его собственного субстрата через его собственные `read` (амплитуды, тики, слои — физическое состояние Φ), а не из внешнего оракула. Оракульные метрики (recall/S/stale_wins/economy, считанные по ledger биографии) остаются harness-side и к ядру не попадают (C7). Канал, которым модель читает собственную физику, — это её обычный `read` по акт-грамматике, не новый интерфейс.
- **Dials are fixed before each run** (C3): результат акта `calibrate` применяется только к *следующему* эпизоду; внутри эпизода ручки не трогаются. Бюджет `self_improvement` заморожен на прогон и самой моделью не увеличивается.
- **Два скана, разные объекты (owner, 07.09):**
  - **`scan` — скан памяти (8-й акт, read-класс, уже легален сегодня).** Акт модели по собственному обращению к физически записанной памяти слоями: амплитуды/тики/слои по записям — сырые данные, не оценки. Может включаться уже в act-грамматику инструкции. Физика: тики не идут (C5); scan ничего не пишет — изменение только отдельными актами (`calibrate`/`connect`/`repeat`); сам скан не оставляет следа — запомнить результат можно только явным актом; бюджет — выключателем (scan ≤ 32). Толкование — целиком модельное.
  - **скан среды (consolidation scan) — скан для усовершенствования самих механизмов памяти.** Объект — не записи, а физика: слои τ, пороги, бюджеты, поведение среды за прошлый эпизод. Это работа уровня `calibrate` и делается им же: модель по данным скана памяти и по последствиям прошлых настроек предлагает изменения механизмов. Без `calibrate`-акта никакого изменения среды не происходит (C4).
  - Важно: оба скана — read-класс; пишет только calibrate (ручки) и обычные акты (память).
- **Ticks do not advance during offline consolidation.** The phase is lived-time-free: the lived-tick counter stops, wall-clock enters only audited stamps. Otherwise the phase ages all of Φ and breaks P1/O-bi-temporal. (Owner adjudication pending, §8.)
- New records (`reconcile` about its own calibration) follow normal act rules; the past is never rewritten (O-5).
- Budget: ≤ 2 dial changes per cycle, ≤ 10 per run; per-cycle change of any dial bounded ×[0.5, 2.0] (τ) or ±50% (floor/ceiling/cap); `act_price`/`dormancy_rate` rejected unconditionally.

**B\*** = the constant set after the last accepted cycle (or the start set if none accepted).

## 7. Phase C — comparison and refutation

On Х, ≥ 3 runs per configuration (fixed temperature, identical wrapper/adapter). Statistics caveat (review 2.4): with n = 3 the "within 1 sd" criterion cannot distinguish "equal" from "underpowered" — at n = 3 the outcome is registered as **exploratory** only; a confirming claim requires n ≥ 10 or a permutation test (registered in advance):

| Arm | Configuration |
|---|---|
| Base | manifest default dials |
| A* | best of Phase A |
| B* | result of Phase B |

Report mean ± sd of S components. **Refutation criteria (declared in advance):**

1. If B* < A* − 1 sd on S: offline consolidation does not beat external search on this corpus — do not embed `calibrate` in arm D; freeze A* for the E1 manifest. Report as such.
2. If B* ≈ A* (within 1 sd): the core self-calibrates to optimizer quality — candidate result for the paper (a separate experiment number from the E-series; not E1).
3. **No-op consolidation outcome (review 3.1):** if the core issues no accepted proposal within the `self_improvement` budget (channels silent — e.g. `died_too_early` empty on a short corpus), B* = the start set by definition; the run is valid and Phase C scores it as such. Silence is an outcome, not a failure.
4. Any constitutional violation (mid-episode retuning, tick advancement in consolidation, oracle-derived metrics reaching the core's context) invalidates the whole series. Budget enforcement is a validator guarantee, not a refutation criterion (review 2.6).

## 8. Owner adjudication required before any run

1. **Tick freeze in offline consolidation** (§6): consolidation does not advance lived ticks (консолидация — не прожитое время, O-4).
2. **`calibrate` (7th) and `scan` (8th) acts** of the act grammar, offline-only; grammar gains sections for both; the one-time-instruction corpus question (dataset divergence note in ACT-GRAMMAR) applies to them as to rules 5–7.
3. **Frozen dials list** (§3): `act_price`, `dormancy_rate` excluded from search permanently.
4. **Физическая ручка `self_improvement`** (§3, §6): самоулучшение вводится как физика среды — перечисленная ручка с бюджетом актов `calibrate`; ядро само крутит ручки в пределах бюджета (владелец решает от 07.09: «для самоулучшения ядро само подкручивает себе ручки»). Сама ручка бюджета ядру неподконтрольна.
5. **Телеметрия как частный случай работы модели**: диагностика ядру — из собственного субстрата через `read`; оракульные метрики — только harness-side (C7). Детальная спецификация канала — отдельное обсуждение.
