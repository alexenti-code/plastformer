# Research Log — 2026-09-06/07: от «Матрёшки» к памяти-состоянию

Научный дневник проекта. Назначение: сохранить ход рассуждений, а не только результат.
Это одновременно (а) история разработки для пре-принта и статей, (б) источник учебных
эпизодов для будущего пластформера (классы R7–R10), (в) страховка от потери хода мысли
между сессиями — архив, который не заменяет состояние, но без которого состояние не с чем строить.

## Эпопея: путь от «Матрёшки» до памяти-состояния

### Фаза 1. Вложенность (26.06 — 28.08.2026)
Первая теория (коммит 539fc32, 26.06.2026): замороженное ядро + память, организованная
как вложенность — «Матрёшка». Публикация v1.0.0 (28.08, Zenodo DOI 22124204/22141019).
Что оказалось неверным: вложенность описывала структуру хранения, а не механизм жизни
памяти; имя столкнулось с Matryoshka Representation Learning; метафора матрёшки не имела
отношения к тому, что память дрейфует по скоростям, а не лежит слоями.

### Фаза 2. Стенд и исполнитель (04.09.2026)
MMI-исполнитель 0.5.1 + Gemma4-12B: первый живой прогон loudness-readout на wall-clock
старении. Ценно: механика чтения громкости работает. Неверно: время по календарю, память
вне модели — стенд решал задачу вместо модели.

### Фаза 3. Оси вместо этапов, PMI, тики (04–05.09.2026)
Переосмысление (ADR-001): одна архитектура, три оси конфигурации (substrate / topology /
act training); PMI — частный случай разнесённой топологии; время — прожитые тики.
«Матрёшка» убрана из терминологии. Это первый большой шаг к доверию модели: акты памяти
— акты самой модели, не пайплайна.

### Фаза 4. Закон и границы (05.09.2026)
ADR-002 (семантика файлов), Конституция v1.0 → v2.x → ADR-004 (журнал и крипто-стирание
исключены из архитектуры — владелец: не надо никакого журнала), security scope withdrawn
целиком. Инцидент goal-drift (05.09): директива владельца повторена 5 раз, агент без
органа памяти молча подменил цель — найдено только владельцем. Этот эпизод стал
Addendum A и одним из мотивов всего направления.

### Фаза 5. Доверие модели к собственной памяти (06.09.2026)
Конституция v3.0 в редакции владельца: O-1 — модель ведёт свою память сама; O-8 — умение
ведёт память задано одним проходом; C1 — семантический субъект один, ядро; C2 — внешнего
решателя нет. Принципиальный сдвиг за три дня: от «система управляет памятью агента»
к «агент ведёт свою память, среда поставляет только физику».

### Фаза 6. Осознание различия (06–07.09.2026)
Владелец сформулировал то, чего нет в литературе: архив (запись, извлекаемая по запросу)
не меняет обработку; состояние (след в носителе, вошедший в forward) — меняет. Триггер —
живой провал архива на самом разработчике: слово «фальсификатор» было запрещено, записано,
и тем не менее тянулось в русскую статью после четырёх напоминаний. Архив не смещает
поведение — он требует извлечения в момент выбора. Тезис «Archive memory vs state memory»
внесён в пре-принт §1 (коммит 825700d). Протокол E1 v1.5 переведён на класс поведения
(конфликтный слой R7–R10) — владелец: цель проекта не метрики «есть память/нет памяти».

### Ключевые решения-повороты (все — решения владельца, зафиксированы в ADR/CHANGELOG)
- вложенность → дрейфующие амплитуды (слои — скорости, не места);
- журнал памяти → исключён (истина в момент записи, не внешний учёт);
- крипто-стирание → опциональная защита, erasure = удаление секции Φ;
- derived traces → не существует как проблема (один отсек = один субъект);
- ABC-схема теста → B vs D (одна пара, переменная — модель);
- executor → RETIRED (физика — внутри артефакта);
- «фальсификация» в русском научном тексте → недопустимо (ложный друг переводчика;
  «falsifier» → «refutation criterion»).

## Датасет: решение и план (решение владельца 07.09.2026)

Текущий organ-dataset (5 синтетических биографий × 200 обменов) не покрывает
зарегистрированный класс: в нём нет конфликтов R7–R10, reconcile показан 1% актов,
забывание не случается по-настоящему (веса — плейсхолдеры). Обучать артефакт на нём —
повторить разрыв «протокол изменился, данные остались вчерашними».

**Решение: датасет строится на базе реального проекта + обязательная сегодняшняя сессия.**

Материал:
1. Хронология проекта (26.06 → 07.09.2026, ~3.5 месяца, 110+ сессий, 201 МБ сырых диалогов).
   Решения появлялись, анализировались, обновлялись, отменялись — это живой слой R7–R10:
   derived traces (была задача → владелец: «бред»), журнал/крипто-стирание (были → ADR-004),
   ABC-схема → B vs D, security scope → withdrawn, «фальсификатор» → refutation criterion
   (живой R9: свой термин против слова владельца, 4 напоминания).
2. Инцидент goal-drift 05.09 — образец R10 (подмена цели на дистанции) в реальности.
3. Сегодняшняя сессия (06–07.09): самый свежий материал — критика «ChatGPT-разработчика»
   и её разбор (придуманный аргумент; пройденный этап, повторенный из-за отсутствия памяти),
   споры о «инъекции», «исполнителях», остывании кофе как неудачной аналогии. Все эпизоды —
   «понимание через поправку» с последствием.
4. Критерий отбора эпизодов: не «факт запомнить», а «после этого эпизода следующие ответы
   должны быть другими» — смещение состояния, а не пополнение справочника.

Формат: MLX messages с акт-потоком (name/repeat/connect/reconcile/read), как organ-dataset;
разметка (эпизод → класс R7–R10 → expected behavior → что изменилось после). Реальные
эпизоды — незаменимый источник негативных примеров «память была, но её перекричал контекст».
