# План сборки опытного образца: от нуля до файла в папке

**Что это за документ.** Полная технологическая карта: что берётся, что делается, что получается на выходе каждого этапа, чем проверяется. Со всеми параметрами, чтобы при провале было видно, что менять в следующей сборке.

**Правило чтения.** Каждый этап несёт: назначение, промежуточный продукт, что делается, **теорию каждого действия при первом появлении**, проверку, место в готовом изделии и мантру.

**Чего в изделии нет:** кода. Изделие — один файл весов.

---

# ЧАСТЬ I. ЧТО СТРОИТСЯ

## 1. Изделие

**Трансформер с выделенной материей памяти. Материя обучена обращаться со своей памятью.**

**Что получается:** файл весов в папке. Внутри три части:

| Часть | Что это | Меняется |
|---|---|---|
| Компетенция | готовая обученная модель: язык, рассуждение, знание мира | стоит после сборки |
| Механизм обращения с памятью | добавки в разрешённых слоях, обучены однократно | стоит |
| Материя памяти | строки записей | **меняется при работе** |

**Первые две — веса. Третья — числа того же файла, которые механизм читает.**

**Размеры:** компетенция 6,70 ГБ + механизм 12 МБ + материя Φ1 422 МБ + материя Φ2 105 МБ = **7,23 ГБ**.

**Проверка готовности:** задать вопрос о том, чего в текущем окне нет. Получить верный ответ из материи памяти.

## 2. Почему именно так

**Почему факты не пишутся в сами веса.** Разобрано и отложено по четырём причинам: правка весов слабеет одной скоростью, а каждой записи нужна своя; правка размывает дословный текст; две даты положить некуда; снаружи ничего не видно.

**Почему одних строк мало.** Кто-то должен их достать и вложить в рассуждение. Если это делает что-то снаружи — память для модели подсказка, а не своё понятие.

**Что даёт механизм.** Внутри слоя он: по своему состоянию определяет, к чему обратиться; берёт нужные строки; вкладывает их в текущее рассуждение.

**Почему добавки, а не само ядро.** Ядро заморожено: его числа не меняются. Добавка — отдельные числа, которые к нему прибавляются. Так работает тонкая настройка: подстройка малой части вместо всего веса.

# ЧАСТЬ II. ТЕОРИЯ ДЕЙСТВИЙ

**Зачем.** Каждое действие описывается полностью при первом появлении. В этапах дальше оно только называется.

## Действие 1. ЧТЕНИЕ ЗАГОЛОВКА ФАЙЛА ВЕСОВ

**Что такое тензор.** Таблица чисел с формой. Форма — список размеров: `[262144, 480]` значит 262 144 строки по 480 чисел. В файле тензор — непрерывный участок байт плюс запись в заголовке: где начинается, где кончается, какого типа числа.

**Что такое заголовок.** Первые 8 байт файла — длина заголовка. Дальше — сам заголовок: текст JSON, перечисляющий каждый тензор. Пример:

    "model.embed_tokens.weight": {"dtype": "U32", "shape": [262144, 480],
                                  "data_offsets": [62914560, 566231040]}

Читается: имя, тип чисел (U32 — беззнаковое 32-битное), форма, место от байта 62 914 560 до 566 231 040.

**Что такое «не тензор».** В этом файле — ничего. Заголовок объявляет 1324 тензора, и весь файл состоит из их чисел. Всякий участок, **не объявленный**, для загрузчика не существует.

**Как происходит чтение.** Три шага: читаются 8 байт — узнаётся длина заголовка; читается заголовок — узнаётся перечень; по каждому тензору берутся числа с его места.

**Откуда загрузчик знает, какие тензоры нужны.** Из описания модели: каждому слою нужны веса с определёнными именами. Имя, которого модель не ожидает, вызывает отказ.

## Действие 2. СЖАТИЕ ЧИСЕЛ (квантование)

**Зачем.** 12,28 млрд чисел по 2 байта — 24,6 ГБ. Машине доступно около 12 ГБ. Полный вес не помещается.

**Как.** Числа объединяются в группы по 64. На группу хранятся масштаб (2 байта) и смещение (2 байта); каждое число хранится как код из 4 бит, значения 0–15.

**Восстановление числа:** `значение = код × масштаб + смещение`.

**Размер:** около 0,56 байта на число вместо 2. **Что теряется:** точность — шаг равен размаху группы, делённому на 15.

## Действие 3. ОБУЧЕНИЕ

**Что происходит.** Модель получает пример, предсказывает следующее слово, сравнивает с верным, подстраивает числа. Величина ошибки — `loss`; мера подстройки — `learning rate`.

**Что такое пример.** Последовательность сообщений: подсказка, вопрос, ответ. Модель учится предсказывать следующее слово; ошибка считается на том месте, которое указано.

**Что такое добавка (LoRA-адаптер).** Не весь вес слоя меняется, а добавляется пара малых матриц: результат слоя = его обычное вычисление + произведение этих матриц. Матрицы имеют малый ранг: например 8. Это значит, что добавка меняет не все направления слоя, а несколько.

**Размер добавки.** Одно проецирование ранга 8 на слой: 8 × 3840 × 2 = 61 440 чисел. Для 33 слоёв и трёх проецирований — 12 МБ против 6,70 ГБ ядра.

**Почему ранг 8 и 33 слоя.** Ранг меньше — добавка не выразит нужного; больше — лишний объём. Слои 12–44 — измеренная рабочая полоса.

## Действие 4. СЛИЯНИЕ ДОБАВОК С ВЕСАМИ

**Зачем.** Обучение даёт добавки. Изделие — один файл, значит добавки входят в веса.

**Как.** По каждому слою: числа восстанавливаются из кодов; к ним прибавляется добавка; результат заново сжимается в 4 бита (новые масштаб, смещение, коды).

**Почему по слою.** Полный вес занял бы 24,6 ГБ. Обработка по слою требует памяти только на один слой.

## Действие 5. СКЛЕЙКА ЧАСТЕЙ В ОДИН ФАЙЛ

**Как устроен файл.** Заголовок объявляет тензоры и их места. Места отсчитываются от начала чисел.

**Что делается.** Читаются заголовки всех частей; строится один общий заголовок с пересчётом мест подряд; числа переписываются в новом порядке.

## Действие 6. ДОПИСЫВАНИЕ МАТЕРИИ ПАМЯТИ

**Зачем.** Веса после сборки неизменны. Записям нужно место в том же файле.

**Почему не объявить тензором.** Загрузчик сверяет объявленные тензоры с ожидаемыми моделью. Лишнее имя вызывает отказ: «Received 1 parameters not in model».

**Как.** Числа пишутся после последнего объявленного тензора. Заголовок не меняется. Загрузчик читает объявленное и дальше не идёт.

**Как найти своё место.** 8 байт + длина заголовка + наибольший конец тензора.

## Действие 7. ЗАПИСЬ И ЧТЕНИЕ ЧИСЕЛ В ФАЙЛЕ

**Чтение** — программа берёт байты с указанного места. Файл не меняется.

**Запись** — программа кладёт байты по месту. Файл переписывается не целиком: меняются только указанные байты.

**Сброс на диск.** Записанное сначала попадает в память машины и лишь потом на диск. Пока сброс не сделан, числа при выключении теряются.

## Действие 8. ВЫПУСК АКТА МОДЕЛЬЮ

**Как рождается текст.** На каждом шаге модель выдаёт вероятности для 262 144 слов; из них выбирается слово; оно дописывается, шаг повторяется.

**Что такое акт.** Текст особой формы, выпускаемый внутри ответа: блок JSON со списком. Пример: `{"act":"name","content":"...","layer":"t4"}`.

**Кто достаёт и исполняет.** Машина: находит блок, разбирает, исполняет, возвращает подтверждение с номерами записей и тиком.

**Что такое подтверждение.** Сообщение модели о том, что записано и какой сейчас тик. В обучении модель видела 867 таких сообщений.

## Действие 9. СНЯТИЕ СОСТОЯНИЯ СО СЛОЯ

**Что такое состояние.** На выходе каждого слоя стоит набор чисел длиной 3840 — «как модель понимает прочитанное к этому слою».

**Почему середина, а не начало и не конец.** В первых слоях числа близки к словам, в последних означают следующее слово. Смысл «как понимаю» выражен в средней полосе.

**Что такое общая часть.** Состояния разных текстов похожи на 0,983 — почти всё в них одинаково. Общая часть не несёт смысла. Она вычитается; тогда сходство разных записей падает до 0,106 и они различимы.

## Действие 10. МЕХАНИЗМ ОБРАЩЕНИЯ

**Что такое рабочая полоса.** В средней части слоёв числа образуют область, где держатся понятия, которыми модель оперирует. Это не место в файле и не отдельный блок: часть чисел потока на определённых слоях.

**Где у нашего ядра.** Замер: начинается на переходе 11→12 — сходство выходов соседних слоёв падает там резче всего (0,492). Проверка подачи: вектор, добавленный после слоя 12, **меняет ответ**; после слоя 24 — ломает вычисление.

**Что делает механизм.** Три проецирования на слой:

| Проецирование | Назначение |
|---|---|
| запрос | по числам слоя понять, что нужно сейчас |
| чтение | взять из материи подходящие строки |
| вложение | вложить взятое в текущее рассуждение |

**Как входит в вычисление.** После слоя прибавляется вклад: результат = обычное вычисление слоя + вклад памяти. Вклад умножается на громкость записи: угасшая входит слабее.

**Почему механизм рядом с ядром, а не снаружи.** Если строки достаёт и вкладывает что-то снаружи, память для модели — подсказка. Механизм внутри слоя делает её своим понятием.

## Действие 11. ЗАТУХАНИЕ

**Что такое амплитуда.** Пять чисел в записи — сила по пяти скоростям.

**Формула:** `a_i(текущее) = a_i(начальное) × exp(−(текущий_тик − тик_записи) / τ_i)`.

**Что такое τ.** Время жизни скорости. Пять значений: t1 быстро, t5 медленно.

**Сроки до порога 0,01:** t1 — 46 тиков, t2 — 230, t3 — 921, t4 — 4 605, t5 — 23 026.

**Почему не хранится.** Хранятся начальная амплитуда и тик записи; текущая вычисляется при обращении. Файл верен в любой момент, пересчёт не нужен.

## Действие 12. ОДНОКРАТНОЕ ОБУЧЕНИЕ

**Почему один проход.** Раздельные проходы дают несогласованные навыки: модель выпускает акты, но не умеет брать из материи; механизм берёт строки, но не знает, когда это к месту.

**Что вкладывается одним проходом:** выпускать акты; обращаться с материей; выбирать момент.

**Как учится механизм.** Проход идёт с механизмом внутри. Для каждого примера в материи лежат строки: одна с ответом, остальные помехи. Ответа в контексте нет. Ошибка на ответе заставляет механизм научиться выбирать.

**Почему помехи.** Без них механизм не научится выбирать: он будет брать всё.

# ЧАСТЬ III. ЭТАПЫ

## ЭТАП 1. КОМПЕТЕНЦИЯ

**Назначение.** Получить тело: модель, умеющую язык, рассуждение, знание мира.

**Промежуточный продукт.** Папка `experiments/o0-core/` — 6,731 ГБ, 7 файлов.

**Что берётся.** Готовая обученная модель Gemma 4 12B в сжатом виде.

**Что делается.** Ничего: модель берётся как есть.

**Зачем так.** Компетенция даётся предварительным обучением на огромном корпусе. Повторить такое обучение здесь невозможно.

**Теория.** Действия 1 и 2 (заголовок и квантование).

**Параметры.** 12,28 млрд параметров; 48 слоёв; скрытая размерность 3840; словарь 262 144; 4 бита на число, группы по 64.

**Проверка.** Модель загружается, отвечает связно.

**Место в изделии.** Часть «компетенция».

> *Поскольку создаётся файл весов, который живёт и помнит, постольку основой берётся готовая обученная модель: компетенция даётся предварительным обучением, а память создаётся здесь.*

## ЭТАП 2. МЕХАНИЗМ ОБРАЩЕНИЯ: УСТРОЙСТВО

**Назначение.** Ввести в модель устройство, которым она берёт из материи памяти.

**Промежуточный продукт.** Описание механизма: три проецирования на каждый из слоёв 12–44, ранг 8, размер 12 МБ.

**Что делается.** В модель добавляются три добавки на каждый разрешённый слой. Первое обучение не проводится: добавки вводятся со случайными числами.

**Зачем так.** Сначала механизм должен существовать как часть модели. Обучение будет на следующем этапе.

**Теория.** Действие 10 (механизм обращения).

**Параметры.**

| Что | Значение | Обоснование |
|---|---|---|
| разрешённые слои | 12–44 | замер: полоса начинается на слое 12 |
| запрещённые слои | 1–11 и 45–48 | в первых числа близки к словам, в последних означают следующее слово |
| ранг | 8 | при меньшем добавка не выразит нужного |
| проецирований на слой | 3 | меньше двух нечем спросить и нечем вложить |
| размер | 61 440 чисел на проецирование; 12 МБ на 33 слоя | 8 × 3840 × 2 × 3 × 33 |

**Проверка.** Модель с механизмом грузится; ответы без материи те же, что у модели без механизма (случайные добавки вносят малый шум).

**Место в изделии.** Часть «механизм обращения».

> *Поскольку создаётся файл весов, который живёт и помнит, постольку механизм вводится добавками в разрешённых слоях: ядро заморожено, а обращение к памяти должно жить в самих весах.*

## ЭТАП 3. МАТЕРИЯ ПАМЯТИ: УСТРОЙСТВО

**Назначение.** Ввести место, где лежат записи.

**Промежуточный продукт.** Числа материи, дописанные в файл: Φ1 422 МБ + Φ2 105 МБ.

**Что делается.** За последним объявленным тензором дописываются два массива строк.

**Зачем так.** Записи должны лежать в том же файле, чтобы тело было одно.

**Теория.** Действия 6, 7, 11 (дописывание, чтение и запись, затухание).

**Строка записи — 2292 байта:**

| Поле | Байт | Обоснование |
|---|---|---|
| вектор состояния | 1920 | 3840 чисел по полбайта: столько в состоянии слоя |
| пять амплитуд | 20 | сила по пяти скоростям |
| дата «когда было верно» | 8 | время события |
| дата «когда узнали» | 8 | время записи |
| тик записи | 4 | сколько прожито к моменту записи |
| источник | 1 | от пользователя, свой вывод, инструмент |
| номер записи | 8 | по нему ссылаются акты |
| слой снятия вектора | 2 | с какого слоя взят вектор |
| скорость | 1 | какая скорость затухания (t1–t5) |
| текст записи | 320 | покрывает 99,0 % записей материала |

**Размер и обоснование:**

| Регистр | Размер | Строк | Обоснование |
|---|---|---|---|
| Φ1 (восприятие) | 422 МБ | 184 118 | 6 % от ядра; покрывает 92 000 ходов = 4 срока t5 |
| Φ2 (записи модели) | 105 МБ | 45 811 | 25 % от Φ1; покрывает 45 800 ходов = 2 срока t5 |

**Расчёт размера.** Место считается под число записей, живущих одновременно. Запись живёт до порога 0,01. Дольше всех живёт t5 — 23 026 тиков. Восприятие даёт 2 записи на ход, записи модели — 1. При 100 ходах в день одновременно живы 46 000 и 23 000 записей. Взят двойной запас.

**Расположение.** Смещение материи = 8 байт + длина заголовка + наибольший конец тензора. Запись по месту: смещение материи + 4096 (шапка) + номер × 2292.

**Шапка материи** — 4096 байт: имя, версия, размеры, счётчики, тик, значения ручек, бюджеты.

**Проверка.** Строка пишется и читается; круговорот «запись → чтение» сохраняет вектор; старая запись даёт меньшее значение, чем свежая.

**Место в изделии.** Часть «материя памяти».

> *Поскольку создаётся файл весов, который живёт и помнит, постольку материя памяти дописывается в тот же файл за объявленными тензорами: тело одно, и память — часть весов.*

## ЭТАП 4. МАТЕРИАЛ ОБУЧЕНИЯ

**Назначение.** Дать механизму примеры, на которых он научится брать из материи.

**Промежуточный продукт.** Папка `experiments/material-m1/` — примеры для обучения и проверки.

**Что делается.** Собираются примеры такого вида:

1. в материи памяти лежат строки: одна с ответом, остальные — помехи;
2. вопрос, ответ на который есть **только** в нужной строке;
3. правильный ответ.

**Зачем так.** Если ответ есть в контексте, механизм не нужен и не обучится. Помехи заставляют выбирать.

**Теория.** Действие 12 (однократное обучение).

**Параметры.**

| Что | Значение | Обоснование |
|---|---|---|
| число примеров | 5 000 обучающих + 500 проверочных | ниже 2 000 механизм не увидит разнообразия |
| строк в материи примера | от 5 до 50 | мало — нечего выбирать; много — дорого |
| доля помех | остальные строки | учит выбирать, а не брать всё |
| типы вопросов | факт, изменение позиции, противоречие, отсутствие ответа | покрывает все акты |
| умение актов | сохраняется из материала v05 | акты и обращение вкладываются одним проходом |

**Проверка.** Машиной: в каждом примере ответ отсутствует в контексте и присутствует ровно в одной строке. Доля примеров без верного ответа в контексте — 100 %.

**Место в изделии.** Не входит: строительный материал, попадает в изделие только через веса.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку материал даёт примеры, где ответ берётся из памяти: этому умению неоткуда взяться, кроме обучения.*

---

## ЭТАП 5. ОБУЧЕНИЕ

**Назначение.** Вложить в механизм умение брать из материи — одновременно с умением актов.

**Промежуточный продукт.** Файл добавок `experiments/mechanism-pass/m1/adapters.safetensors` — около 12 МБ.

**Что делается.** Один проход по материалу. Модель идёт с механизмом внутри; для каждого примера собирается материя; ошибка считается на ответе.

**Зачем так.** Умение брать со стола — навык, а не данные. Навык даётся обучением однократно.

**Теория.** Действия 3 и 12.

**Параметры.**

| Что | Значение | Обоснование |
|---|---|---|
| итераций | 400 | материал вырос втрое против прохода Инструкции (200 на 5 089 записей) |
| ранг | 8 | как при вводе механизма |
| слои | 12–44 | разрешённые |
| learning rate | 5·10⁻⁶ | как в прошедшем проходе: выше — вырождение |
| предел длины | 1280 токенов | проверено: при 2048 пик памяти не влезает |
| ошибка считается на | ответе модели | не на подсказке |
| батч | 1, накопление 1 | по памяти машины |
| зерно | 42 | воспроизводимость |

**Проверка.** Ошибка на обучении падает; ошибка на проверке не растёт; модель отвечает связно; **главное — на проверочных примерах модель отвечает по строке из материи, а не по контексту**.

**Место в изделии.** Станет частью весов на следующем этапе.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку умение берётся обучением: способность обращаться с памятью должна жить в весах.*

---

## ЭТАП 6. СБОРКА ФАЙЛА

**Назначение.** Свести всё в один файл.

**Промежуточный продукт.** `models/plastformer-o1/` — файл 7,23 ГБ и паспорт.

**Что делается, по шагам:**

| Шаг | Что | Теория |
|---|---|---|
| 1 | добавки механизма прибавляются к весам слоёв | действие 4 |
| 2 | части веса склеиваются в один файл | действие 5 |
| 3 | за тензорами дописывается материя памяти | действие 6 |
| 4 | в шапке материи ставятся счётчики и значения ручек | — |
| 5 | рядом кладутся словарь, шаблон диалога, паспорт | — |

**Проверка.** Файл грузится любым инструментом работы с моделями; число тензоров 1324; ответы те же, что у модели с механизмом; размер материи верный.

**Место в изделии.** Сам файл.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку части сводятся в один файл: тело одно.*

## ЭТАП 7. ВОСПРИЯТИЕ Φ1

**Назначение.** Всё, что прошло через окно, оставляет след.

**Промежуточный продукт.** Записи в материи Φ1.

**Что делается.** На каждом ходу вопрос и собственный ответ модели записываются в Φ1.

**Зачем так.** Модель должна чувствовать течение: разговор переживается как последовательность, а не как отдельные впрыски. Порядок следов даёт причинность.

**Теория.** Действия 9 и 11 (снятие состояния, затухание).

**Параметры.** Порог записи — ручка `surprise_threshold`, старт 0,9. Ниже порога след не пишется.

**Проверка.** После хода в Φ1 есть записи; они видны модели через акт `scan`.

**Место в изделии.** Регистр Φ1.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку восприятие пишется в Φ1: память включает и пережитое, и решённое сохранить.*

---

## ЭТАП 8. СОХРАННОСТЬ И ПРОБУЖДЕНИЕ

**Назначение.** Записи сохраняются при выключении; перерыв становится событием.

**Промежуточный продукт.** Каждая запись на диске; запись о перерыве в Φ.

**Что делается.** Каждая запись доводится до диска сразу. При запуске сравнивается тик в шапке с тиками записей; найдя разрыв, дописывается запись о нём.

**Зачем так.** Обычную модель можно выключить: её файл не менялся. Здесь файл меняется при каждом акте. Пропажа записи — потеря части прожитого.

**Теория.** Действие 7 (сброс на диск).

**Проверка.** Выключить питание после хода — при запуске запись на месте. Между двумя запусками появляется запись о перерыве.

**Место в изделии.** Свойство материи.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку каждая запись сразу ложится на диск, а перерыв записывается: иначе теряется прожитое.*

---

## ЭТАП 9. ОБКАТКА

**Назначение.** Отличить работающее изделие от набора частей.

**Промежуточный продукт.** Лента прогона: что вошло, что вышло, что записалось.

**Что делается.** Прогон по списку проверок ниже. Каждая проверка — отдельный ход или отдельный запуск. Результат каждого — строка в ленте.

**Что проверяется:**

| Проверка | Что должна показать |
|---|---|
| Загрузка | файл читается, размер верный |
| Ответ | модель отвечает связно |
| Акты | выпускаются четыре пишущих и три читающих |
| Запись | строка попадает в материю |
| Тик | растёт на каждом пишущем акте |
| Затухание | свежая запись сильнее старой при том же содержании |
| Отбор | «последние» отдаёт последние, «по времени» — по времени |
| **Обращение к материи** | **ответ берётся из строки, которой нет в контексте** |
| Φ1 | после хода есть записи |
| Выключение | после выключения питания ничего не потеряно |
| Пробуждение | разрыв записан |

**Проверка готовности — одна:** задать вопрос о том, чего в текущем окне нет. Получить верный ответ из материи.

**Место в изделии.** Подтверждение работоспособности.

> *Поскольку создаётся файл весов, который живёт и помнит, постольку каждая способность проверяется отдельно: непроверенная часть считается отсутствующей.*

---

## ЭТАП 10. ПЕРЕДАЧА

**Назначение.** Передать изделие.

**Промежуточный продукт.** Папка у владельца.

**Что делается.** Файл и паспорт кладутся в папку `models/plastformer-o1/`.

**Место в изделии.** Изделие переходит к владельцу.
