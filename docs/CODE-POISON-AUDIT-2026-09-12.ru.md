## 0.1. ГЛАВНОЕ: три разных правила чтения в одном проекте

Это самый тяжёлый случай аудита. Один и тот же акт `read mode="last"` понимается тремя способами:

| Кто | Правило | Код | Что вернёт на Φ из 5 записей (громкость 5,4,3,2,1 у id 1,2,3,4,5) |
|---|---|---|---|
| **Обучение** | «хвост хранилища» — последние записанные | `experiments/organ-dataset/gen_acts.py:173-175` — `recs = self.records[-count:]` | id **[3, 4, 5]** |
| **Грамматика и `phi.py`** | «N самых громких по амплитуде» | `plastformer/phi.py:263-287` — сортировка по `loudness` | id **[1, 2, 3]** |
| **Круг возврата** | самые СТАРЫЕ (ошибка среза) | `plastformer/loop.py:204-205` — `sorted(..., key=-id)[-n:]` | id **[3, 2, 1]** |

Проверено **выполнением** на тестовой Φ (не чтением кода). Три разных ответа на один акт.

Последствия:
1. **Модель учили правилу 1, изделие исполняет правило 3.** Она читает «последние», получает самое старое и тихое.
2. **Грамматика (`act-grammar-v0.2-ru.md:84`) обещает правило 2** — и обучение, и изделие ей противоречат.
3. Отсюда, вероятнее всего, и **зацикливание на `read`**, названное в `TECHNICAL-STATE.md:68`: модель читает, не находит нужного и читает снова.
4. Числа проверены на материале: все 68 вызовов `read mode="last"` в биографиях дают payload, **ни разу** не равный top-N по громкости.

**Что чинить первым:** привести три места к одному правилу. Какое правило верное — решает владелец. Грамматика говорит «по громкости»; материал учит «хвост»; код круга исполняет третье.

## 3. Дефект вне шести типов: закон затухания у изделия и у обучения РАЗНЫЙ

**Обучение** (`experiments/organ-dataset/gen_acts.py:159-163`, `TAU_TICKS` — строка 32):
```python
def weight(self, rec):
    repeats = sum(1 for r in self.records if r["act"] == "repeat" and rec["id"] in r["refs"])
    dn = self.tick - rec["record_tick"]
    return round((1 + repeats) * math.exp(-dn / TAU_TICKS[rec["layer"]]), 3)
```
Проверка на материале v04: 153 записи из блоков `<<ENV>>`, из них **150 совпали** с `exp(-dn/tau_layer)` с точностью 0,002 (три отклонения — записи с `repeat`).

**Изделие** (`plastformer/phi.py:403-420`):
```python
taus = _np.array([base / 8.0, base / 3.0, base, base * 2.0, base * 4.0], dtype=_np.float32)
```
плюс `loudness` = **максимум** по пяти компонентам (`phi.py:423-427`).

Числа для одной и той же записи:

| слой | dn | обучение `exp(-dn/τ)` | изделие `max_i a_i·exp(...)` |
|---|---|---|---|
| t2 (τ=50) | 25 | 0,607 | **0,882** |
| t2 (τ=50) | 50 | 0,368 | **0,779** |
| t4 (τ=1000) | 500 | 0,607 | **0,882** |
| t4 (τ=1000) | 1000 | 0,368 | **0,779** |

Запись, которую модель в обучении видела бы «почти угасшей» (0,368), изделие показывает как «ещё громкую» (0,779). И след **никогда не опускается ниже 1/8** исходной амплитуды, потому что самая медленная компонента имеет τ = 4·base.

**Почему это важно.** Канон (`docs/CONSTITUTION.ru.md:39`, О-10): «Громкость следа для показа — `(1+repeats)·Σ_i w_i·exp(−Δn/τ_i)`» — **сумма**. Код считает **максимум**. И то, и другое отлично от того, что видело обучение (одна компонента на слой).

**Что должно быть:** решить и назвать. Либо `weight_of` считает по закону обучения; либо канон и материал пересобрать под пять компонент. Сейчас документы считают вопрос закрытым («Теория §4, О-10»), а числа не сходятся. **Выбор закона — за владельцем.**

#### 1. gen_acts.py — построение потока актов

#### 1.1. `read mode:"last"` обучен как «хвост хранилища», а не как «N самых громких» — тип 1

**Строки 173-175:**
```python
    def act_read_last(self, count, lead):
        recs = self.records[-count:]
        return ({"act": "read", "mode": "last", "count": count}, recs, lead)
```

Что означает `last` по утверждённой грамматике (`experiments/act-grammar/act-grammar-v0.2-ru.md`, строка 84):
> `mode:"last"` — N самых громких следов по амплитуде: без релевантности, без поиска по словам, без рейтинга содержания (C2).

Тот же смысл в изделии: `plastformer/phi.py`, `phi_read` — «out.sort(key=lambda r: -r["loudness"]); out = out[:n]».

Факт по данным: во всех 5 биографиях **68 вызовов** `read` с `mode:"last"`; ответ (payload) **ни разу** не равен
top-N по громкости, посчитанной собственной функцией генератора `weight()` (строки 159-163). Пример: `bio-01`,
сообщение 14, запрошены записи `[7, 8, 9, 10, 11]`, а top-5 по весу на тике 11 — `[1, 2, 3, 4, 11]`.

**Почему это отрава.** Материал учит: «прочитать последние» = «взять последние записанные». Это не то, что
делает изделие (`phi_read` отдаёт по громкости) и не то, что обещает грамматика. Документы считают демонстрацию
чтения сделанной.
**Что должно быть вместо.** Либо `recs`, отсортированные по `self.weight` и обрезанные по `count` (тогда данные
совпадут и с грамматикой, и с `phi.py`), либо честное имя режима (`mode:"tail"`) и правка грамматики.
Выбор — за владельцем.

оценка для подтверждений»), либо генератор считает спектр через `phi.decayed`.

#### 7. Дефекты данных, не подпадающие под шесть типов (проверены)

1. **Тики идут назад внутри одного примера.** `read_payload` (gen_acts, строка 165) ставит `"tick": self.tick`

2. **`reconcile` считает «прожито» не по тем тикам, что видит модель.** gen_acts, строки 372-386: `dn` считается

   подтверждение чтения в том же примере показывает тик 125. Проверено по всем 10 записям `reconcile` —
   расхождение везде.
3. **Демонстраций `reconcile` — 10 на весь материал** (2 на биографию); README это признаёт
   («minimally demonstrated»). Это единственный акт с таким объёмом.
4. **`read` описан двумя разными способами:** 68 вызовов `mode:"last"` (хвост хранилища, §1.1) и 60 `mode:"ids"`.
5. **README organ-dataset расходится с файлами.** Строка 52: «Training examples: **1133** — train 1017 /
   valid 116»; фактически в `organ-dataset/output/` — **1064 + 119 = 1183** (проверено подсчётом и прогоном
   `emit_mlx.py`). Строка 90: «sliding window of 14 transcript messages», фактически `WINDOW = 4`.
   Строка 98 перечисляет `record_tick` среди полей акта — верно до правки 12.09.2026.
   Шапка README (строка 3) помечена SUPERSEDED, но датирована 10.09.2026, а расхождения возникли из-за сборок
   11-12.09.
6. **Имя `_message_no` хранит время.** gen_acts, строка 87. Во всех `acts/bio-*.json` это ISO-строка.
7. **`validate()` не проверяет `evidence` калибровки** и не проверяет ссылки на записи, созданные позже
   (см. §1.3, §3.7).
